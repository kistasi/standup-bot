# AGENTS.md

This file provides guidance to agentic coding tools when working with code in this repository.

## Overview

`standup-bot` is an early-stage Go application (module `github.com/kistasi/standup-bot`) that assembles standup digests from GitHub project activity (and, optionally, Google Calendar meetings), summarizes them with Claude, and optionally posts the result to Slack. A second, CLI-only command writes a monthly report to a markdown file. Either report can also be backed up to Google Drive. It is organized into a thin `main` plus eight internal packages:

- `main.go` — entry point. `dispatch(args)` picks the command: no arguments runs `run()` (the standup, which is what the scheduled workflow invokes), `monthly` runs `runMonthly()`, anything else is an error naming the command. `run()` loads config, builds a `gh.Client`, fetches the viewer's project items and recent commits, fetches calendar events when `cfg.CalendarEnabled()` (else `events` stays nil), renders them via `internal/render`, feeds the digest to `claude.Ask` for a standup summary, prints it, and — when `SLACK_WEBHOOK_URL` is set — posts it via `slack.Post`. When `cfg.DriveEnabled()` it then backs the summary up via the shared `backup()` helper, uploading straight from memory (the standup writes no local file) under `standupName(now)` — `<date>-standup.md`, one file per day. `runMonthly()` loads the same config, asks for a year and month via `monthly.Ask`, fetches the project items, the viewer's pull requests (`MyPullRequests` — the standup passes `nil` there), and the commits in that month's window, renders the digest (no calendar), summarizes it with `claude.MonthlySystem`, writes it with `monthly.Write`, prints the path, and — when `cfg.DriveEnabled()` — reads that file back and backs it up under the same basename; it never posts to Slack. `main` only maps a `dispatch()` error to stderr + exit code.
- `internal/config` — `Load()` resolves configuration from the environment (loading `.env` via `godotenv`). Required vars (no defaults/fallbacks; `Load()` errors naming any unset or malformed one): `GH_PAT`, `GH_ORG`, `GH_PROJECT` (int), and `AUTHOR_EMAILS` (comma-separated git emails). Optional vars: `SLACK_WEBHOOK_URL` (when set, the summary is posted to Slack; when empty, only printed) and the `GOOGLE_*` group. `GOOGLE_CREDENTIALS_JSON` is one credential shared by two independent features, each switched on by its own variable: `GOOGLE_CALENDAR_ID` (calendar events in the digest, `Config.CalendarEnabled()`) and `GOOGLE_DRIVE_FOLDER` (the Drive backup, `Config.DriveEnabled()`). `Load()` errors on any half-configuration: a switch without credentials, or credentials with neither switch. `Config.Since()` returns the start of the reporting window computed from the weekday (via the injectable `since(now)`): a weekday reaches back one day, but Monday reaches back three (across the weekend to Friday). There is no lookback variable — the window can't drift out of sync with the Mon–Fri schedule. `Config.PeriodLabel()` (via `periodLabel(now)`) names that window for the standup message — "yesterday" on weekdays, "Friday" on Monday — and `main` feeds it to `claude.StandupSystem`.
- `internal/render` — `Digest(project, pulls, commits, events, number, since)` formats the digests into the indented plain-text report (project items, then pull requests, then commits, then calendar events) that is printed or summarized. `pulls` and `events` may both be nil, in which case that section is omitted — the standup passes nil for `pulls` (it reports the board and commits only), and `events` is nil when the calendar is disabled. `writePulls` skips any pull request whose URL already appeared among the project items, so a pull request on the board is reported once, in the project section. Each project-item line leads with the item's `Type` (`Issue` / `PullRequest` / `DraftIssue`) so a summarizer can tell tickets from pull requests. Descriptions are printed indented under each entry so the whole thing can be fed to the Claude API.
- `internal/gh` — typed wrapper around the GitHub GraphQL v4 API (via `shurcooL/githubv4`). `New(token)` builds a bearer-authenticated client.
  - Both fetchers take a half-open window `[since, until)`: the standup passes `time.Now()` as `until`, the monthly report passes the first instant of the next month.
  - `MyProjectItems(ctx, org, number, since, until)` pages through an org ProjectV2, flattening Issue / PullRequest / DraftIssue nodes into a `ProjectDigest` filtered to the PAT owner (`viewer`) and to items updated in the window. Each `Item` carries the issue/PR/draft `Body`.
  - `MyPullRequests(ctx, org, since, until)` pages through `viewer.pullRequests` newest-updated-first (stopping at the first one updated before `since`), keeping those in `org` and inside the window, and returns a `PullRequestDigest`. It exists because `MyProjectItems` only sees pull requests someone added to the project board; release pull requests are dropped by the same `isReleaseCommit` headline check used for commits. Only the monthly report fetches these.
  - `OrgCommits(ctx, org, since, until, emails)` pages through the org's repositories newest-pushed-first (stopping once a repo's last push predates `since` — `until` can't shorten that walk, since a recently pushed repo may still hold in-window commits) and collects default-branch commits authored by any of `emails`, returning a `CommitDigest`. Each `Commit` carries the headline (`Message`) and full `Body`. Filtering is by **author email** (`author:{emails:...}`), not GitHub account: the contributions API and `author:{id:...}` filter both require the commit email to be linked to the account, and silently return nothing when it isn't. Release-automation commits (headline starting `release `) and merge commits (2+ parents) are skipped as standup noise.
- `internal/gcal` — wrapper around the Google Calendar v3 API (`google.golang.org/api/calendar/v3`). `New(ctx, credsJSON, calendarID)` builds a read-only client from a Google credentials JSON via `option.WithCredentialsJSON` — either **authorized-user** creds (from `gcloud auth application-default login --scopes=…calendar.readonly`, reading the signed-in user's own calendar with full event details — the approach used here, since Workspace domains often restrict external calendar sharing to free/busy) or a **service-account** key (needs the calendar shared read-only with the SA email). `Events(ctx, since, until)` lists the calendar's timed events in the window (`SingleEvents(true)` expands recurrences; paginates on `NextPageToken`), returning a `Digest`. `toEvent` drops standup noise: cancelled instances, all-day events (a `Start.Date` with empty `Start.DateTime`), and events the owner declined (the `Self` attendee's `ResponseStatus == "declined"`).
- `internal/gdrive` — wrapper around the Google Drive v3 API (`google.golang.org/api/drive/v3`, already in the module `internal/gcal` depends on — the backup added no new dependency). `New(ctx, credsJSON, folderName)` builds a client from the *same* credentials JSON as `gcal`, scoped to **`drive.file`** — a non-sensitive scope needing no Workspace admin grant and no app verification, which grants access only to files this app created. That scope is why the folder is configured by **name, not ID**: a folder made by hand in the Drive UI is invisible under `drive.file`, so `ensureFolder` looks for the bot's own folder of that name and creates it in My Drive on first use (the ID is then cached on the `Client` for the rest of the run). `Upload(ctx, name, content)` looks the name up in that folder and *updates in place* when it exists, so re-running a report keeps one file and one stable link per period, mirroring how `monthly.Write` overwrites its local copy; it returns the file's `webViewLink`. `escape` quotes names for Drive's query syntax (single-quote delimited, backslash-escaped).
- `internal/monthly` — the CLI-only monthly report's plumbing (no network calls of its own). `Ask(in, out, now)` prompts for a year and month, both defaulting to the month before `now`, validating ranges and reading both answers from one buffered reader. `Window(year, month)` returns the half-open `[since, until)` covering that month in the local timezone. `Label(year, month)` names it ("June 2026") for the heading and prompt. `Write(dir, year, month, report)` creates `dir` (the exported `Dir` = `reports`, gitignored), writes `<year>-<month>-monthly-report.md` trimmed to start on its heading and end in exactly one newline (the model sometimes pads its reply), overwriting a previous run, and returns the path.
- `internal/claude` — thin wrapper around the Anthropic Messages API. `New()` builds a client; `Ask(ctx, system, prompt)` sends a single prompt and returns the reply. `StandupSystem(period)` builds the system instruction used to turn a digest (project items, commits, and calendar meetings) into a standup update; `period` is the reporting-window label that opens the message ("My <period> was about:") — `main` passes `cfg.PeriodLabel()` ("yesterday" on weekdays, "Friday" on Monday, matching `Since`). `MonthlySystem(period)` is the monthly counterpart: same digest shape, but it also covers the off-board pull request section, asks for a themed markdown report opening on a `# <period>` heading rather than a chat message, and — unlike the standup, which omits links — it requires every bullet to cite the tickets and pull requests behind it as markdown links on their titles (draft tickets are named without a link, having no URL).
- `internal/slack` — posts messages to a Slack incoming webhook using stdlib `net/http` (no new deps). `New(webhookURL)` mirrors `gh.New(token)` (the URL is the credential); `Post(ctx, text)` sends `{"text": text}` as JSON with a 10s-timeout client and treats any non-`200`/non-`ok` response as an error. `toMrkdwn` first converts the one bit of standard Markdown Claude emits that Slack's mrkdwn spells differently — `**bold**` becomes `*bold*` (`` `code` `` is the same in both, and the prompt omits links). `main` posts only when `SLACK_WEBHOOK_URL` is configured.

## Commands

```bash
go run .          # run the standup
go run . monthly  # write a monthly report (prompts for year/month)
go build ./...    # compile
go test ./...     # run all tests (every internal package has tests)
go test -run TestName ./path  # run a single test
go mod tidy       # sync go.mod/go.sum after changing imports
```

A `Makefile` wraps these for humans (`make` alone lists the targets: `standup`, `monthly`, `build`, `test`, `check`, `vet`, `fmt`, `tidy`, `clean`). It is a convenience wrapper only — no build logic lives there, and CI calls the `go` commands directly. `make check` runs fmt + vet + test, i.e. everything `.github/workflows/test.yml` checks; note `make fmt` only _reports_ unformatted files rather than rewriting them.

Requires Go 1.26+.

## Configuration

Env vars are loaded from a `.env` file via `godotenv.Load()` in `config.Load()` (`.env` is gitignored). Every variable below is required except `SLACK_WEBHOOK_URL` and the calendar pair — `config.Load()` errors naming any required one that is unset (or malformed). Copy `.env.example` to `.env` and fill in:

- `GH_PAT` — GitHub personal access token.
- `ANTHROPIC_API_KEY` — read automatically by the Anthropic SDK. `claude.New()` / `anthropic.NewClient()` take no explicit key argument. Always needed, since the digest is always summarized with Claude.
- `AUTHOR_EMAILS` — comma-separated git emails to attribute commits to in `OrgCommits`. `config.Load()` errors if it yields no email.
- `GH_ORG` / `GH_PROJECT` — the project the digest is built from (`GH_PROJECT` is an int). The reporting window is no longer configurable; `config.Since()` derives it from the weekday.
- `SLACK_WEBHOOK_URL` — optional Slack incoming-webhook URL. When set, the summary is posted there in addition to being printed; when empty, it is only printed.
- `GOOGLE_CREDENTIALS_JSON` — optional; the credential shared by both Google features. A Google credentials JSON (single line): authorized-user creds from `gcloud auth application-default login`, or a service-account key. List every scope you need in **one** login, since the command replaces the whole ADC file: `--scopes=openid,https://www.googleapis.com/auth/calendar.readonly,https://www.googleapis.com/auth/drive.file`. Setting it without switching on at least one feature below is an error.
- `GOOGLE_CALENDAR_ID` — optional; switches calendar events into the digest. The calendar to read (your email, or `primary`). With a service account, the calendar must be shared with the SA email. Needs `GOOGLE_CREDENTIALS_JSON`.
- `GOOGLE_DRIVE_FOLDER` — optional; switches on the Drive backup of finished reports (both the daily standup and the monthly report). The **name** of the My Drive folder to upload to, e.g. `standup-bot` — a name rather than an ID because `drive.file` only sees files the bot created, so the bot creates the folder itself on first run (see `internal/gdrive`). Needs `GOOGLE_CREDENTIALS_JSON` carrying the `drive.file` scope. A service-account credential technically works but puts the files in the service account's own Drive, where no human can browse them.

## Scheduling

`.github/workflows/standup.yml` runs `go run .` on a cron (`0 5 * * 1-5` — 05:00 UTC, Mon–Fri) and via `workflow_dispatch`. That's 07:00 Budapest during summer (CEST); GitHub cron is UTC with no DST support, so in winter (CET) it lands at 06:00 Budapest. Cron may be delayed a few minutes under GitHub load. Secrets `GH_PAT` / `ANTHROPIC_API_KEY` / `SLACK_WEBHOOK_URL` / `GOOGLE_CREDENTIALS_JSON` and repo Variables `GH_ORG` / `GH_PROJECT` / `AUTHOR_EMAILS` / `GOOGLE_CALENDAR_ID` / `GOOGLE_DRIVE_FOLDER` feed the job's env (the `GOOGLE_*` group is optional; each feature variable needs the credential alongside it). The scheduled standup backs itself up to Drive whenever `GOOGLE_DRIVE_FOLDER` is set — note the secret must then hold a credential whose grant includes `drive.file`, so re-run the ADC login and refresh the secret when adding it. The reporting window is derived from the weekday in `config.Since()` (Monday reaches back to Friday, other weekdays to yesterday), so Fri + the weekend are covered with no lookback variable to tune.

The monthly report has no automation by design: it is interactive (it prompts on stdin) and run by hand with `go run . monthly`. Its Drive backup rides along with that manual run. Nothing in `.github/workflows` invokes it, and the standup workflow's bare `go run .` is unaffected by the subcommand dispatch.

`.github/workflows/test.yml` is CI: on push to `main`, on any pull request, and via `workflow_dispatch` it runs `go build ./...`, `go vet ./...`, and `go test -race -cover ./...`. It needs no secrets or variables.

## Notes

- The Claude model is referenced via SDK constants (e.g. `anthropic.ModelClaudeOpus4_8`), not raw strings.
- `internal/gh` authenticates by injecting a `Bearer` token through a custom `http.RoundTripper` that clones the request before mutating headers — follow that pattern rather than mutating requests in place.
- GraphQL selections are expressed as Go structs with `graphql:"..."` tags, including inline fragments (`... on Issue`); `Item` flattens the union content into one shape.
