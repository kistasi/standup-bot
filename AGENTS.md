# AGENTS.md

This file provides guidance to agentic coding tools when working with code in this repository.

## Overview

`standup-bot` is an early-stage Go application (module `github.com/kistasi/standup-bot`) that assembles standup digests from the viewer's own GitHub pull requests and commits (and, optionally, Google Calendar meetings), summarizes them with Claude, and optionally posts the result to Slack. Project/board tickets are deliberately out of scope — the digest follows the code — and release branches are reported as *delivered*. Tracked time from Toggl is folded in when configured. A second, CLI-only command writes a monthly report to a markdown file. Either report can also be backed up to Google Drive. It is organized into a thin `main` plus nine internal packages:

- `main.go` — entry point. `dispatch(args)` picks the command: no arguments runs `run()` (the standup, which is what the scheduled workflow invokes), `monthly` runs `runMonthly()`, anything else is an error naming the command. `run()` loads config, builds a `gh.Client`, fetches the viewer's pull requests and recent commits, fetches calendar events when `cfg.CalendarEnabled()` (else `events` stays nil) and tracked time via the shared `trackedTime()` helper, renders them via `internal/render`, feeds the digest to `claude.Ask` for a standup summary, prints it, and — when `SLACK_WEBHOOK_URL` is set — posts it via `slack.Post`. Before any of that, `hasActivity()` gates the run: an empty window (no pull requests, no commits, no meetings, and no ticket-less time entries) prints a stderr note and returns, so nothing is summarized, posted or backed up. It mirrors what `render.Digest` would actually print — a nil optional digest is an absent section rather than an empty one, and ticketed time entries don't count because render drops them — so the bot never announces that it has nothing to announce. It then backs the summary up via the shared `backup()` helper, uploading straight from memory (the standup writes no local file) under `standupName(now)` — `<date>-standup.md`, one file per day. `backup()` owns the `cfg.DriveEnabled()` check and the "Backed up to …" line, so both commands call it unconditionally; it is a no-op when the Drive backup is off. `trackedTime()` is the same shape for Toggl: it returns `nil, nil` when `cfg.TogglEnabled()` is false, and it swallows `toggl.ErrBeyondLookback` into a stderr warning — an old monthly report is still worth writing without its hours, so only that one error is downgraded. `run()` takes one `time.Now()` for the whole run, so the window's end and the backup filename agree even across midnight. `runMonthly()` loads the same config, asks for a year and month via `monthly.Ask`, fetches the viewer's pull requests and the commits in that month's window (the same two fetchers as the standup) plus `trackedTime()`, renders the digest (no calendar), summarizes it with `claude.MonthlySystem`, writes it with `monthly.Write`, prints the path, and — when `cfg.DriveEnabled()` — reads that file back and backs it up under the same basename; it never posts to Slack. `main` only maps a `dispatch()` error to stderr + exit code.
- `internal/config` — `Load()` resolves configuration from the environment (loading `.env` via `godotenv`). Required vars (no defaults/fallbacks; `Load()` errors naming any unset one): `GH_PAT`, `GH_ORG`, and `AUTHOR_EMAILS` (comma-separated git emails). There is no project/board variable — tickets are not fetched. Optional vars: `SLACK_WEBHOOK_URL` (when set, the summary is posted to Slack; when empty, only printed), `TOGGL_API_TOKEN` (`Config.TogglEnabled()` — the token is the whole configuration, so unlike the Google features there is no second variable and no half-configured state to detect), and the `GOOGLE_*` group. `GOOGLE_CREDENTIALS_JSON` is one credential shared by two independent features, each switched on by its own variable: `GOOGLE_CALENDAR_ID` (calendar events in the digest, `Config.CalendarEnabled()`) and `GOOGLE_DRIVE_FOLDER` (the Drive backup, `Config.DriveEnabled()`). `Load()` errors on any half-configuration: a switch without credentials, or credentials with neither switch. `Config.Since()` returns the start of the reporting window computed from the weekday (via the injectable `since(now)`): a weekday reaches back one day, but Monday reaches back three (across the weekend to Friday). There is no lookback variable — the window can't drift out of sync with the Mon–Fri schedule. `Config.PeriodLabel()` (via `periodLabel(now)`) names that window for the standup message — "yesterday" on weekdays, "Friday" on Monday — and `main` feeds it to `claude.StandupSystem`.
- `internal/render` — `Digest(pulls, commits, events, times, since)` formats the digests into the indented plain-text report (pull requests, then commits, then calendar events, then tracked time) that is printed or summarized. `events` and `times` may each be nil — when the calendar or Toggl is disabled, and `times` also when the window predates Toggl's lookback — in which case that section is omitted; both commands pass the same non-nil `pulls` and `commits`. `writeTimes` renders **only** the entries that name no ticket: an entry with one is skipped outright, so neither its description nor its duration reaches the digest — the pull request and commit sections already account for that work, and no figure for how long it took is reported anywhere. It substitutes `(no project)` / `(no description)` for the fields Toggl leaves empty and appends `(still running)` to a live timer, so no column can render blank; `plural` picks the footer's "entry"/"entries". The footer's count and duration are both accumulated from the entries actually written rather than read off `Digest.Unflagged`, so the summary cannot contradict the lines above it. Each pull request line carries its repo, state, **head branch**, title and URL. A released entry (a `Delivered` pull request or commit) gets the trailing `\tDELIVERED` marker written by `mark()`; both Claude prompts explain that marker, so a release branch reads as shipped rather than as one more merge. Descriptions are printed indented under each entry so the whole thing can be fed to the Claude API.
- `internal/gh` — typed wrapper around the GitHub GraphQL v4 API (via `shurcooL/githubv4`). `New(token)` builds a bearer-authenticated client. Beneath the auth transport sits `retryTransport`, which re-sends a request after a 502/503/504 (GitHub's transient "Unicorn" gateway errors) with 2s/5s/10s pauses, rewinding the body via `GetBody`; it is safe because every query is a read. Any other status, or the last failure, is returned unchanged.
  - Both fetchers take a half-open window `[since, until)`: the standup passes `time.Now()` as `until`, the monthly report passes the first instant of the next month.
  - `MyPullRequests(ctx, org, since, until)` pages through `viewer.pullRequests` newest-updated-first (stopping at the first one updated before `since`), keeping those in `org` and inside the window, and returns a `PullRequestDigest`. Each `PullRequest` carries its head `Branch` and a `Delivered` flag set when `isReleaseBranch(branch)` or `isReleaseCommit(title)` holds — a release pull request is the delivery, so it is kept and flagged rather than dropped. Both commands fetch these.
  - `OrgCommits(ctx, org, since, until, emails)` pages through the org's repositories newest-pushed-first (stopping once a repo's last push predates `since` — `until` can't shorten that walk, since a recently pushed repo may still hold in-window commits) and collects default-branch commits authored by any of `emails`, returning a `CommitDigest`. Each `Commit` carries the headline (`Message`) and full `Body`. Filtering is by **author email** (`author:{emails:...}`), not GitHub account: the contributions API and `author:{id:...}` filter both require the commit email to be linked to the account, and silently return nothing when it isn't. Merge commits (2+ parents) are skipped as noise, but release commits (headline starting `release `) are kept with `Delivered` set — they are the record of what shipped (`appendCommits`). `isReleaseBranch` recognizes `release`/`releases` optionally followed by `/`, `-`, `_` or `.` (so `release/2026-07-20` and `releases-1.2.3` count, `released` does not).
    - **Both** connections are paged. The repository walk reads 100 commits of each repo's history inline; when a repo has more than that in the window — a month of a busy repo, say — `repoCommits` follows up with a per-repository `repository(owner:,name:)` query (splitting `nameWithOwner` on `/`) until the history is exhausted. The inner connection needs its own query because one cursor variable cannot resume several repositories at once. `pageInfo` and `historyPage` are the selections shared by both fetchers.
- `internal/toggl` — wrapper around the Toggl Track API v9 using stdlib `net/http` (no new dependency; the maintained-Go-client landscape is thin). `New(token)` mirrors `gh.New(token)` — the token is the credential — and authenticates via a cloning `basicAuth` RoundTripper that sends it as the Basic **username** with the literal `api_token` as the password, which is Toggl's token scheme. `Entries(ctx, since, until)` GETs `/me/time_entries` once (the endpoint has no pagination) with `meta=true`, which resolves `project_name` and `client_name` inline and so avoids a per-entry lookup the **30-requests-per-hour user-scoped quota** could not afford — that quota applies on every plan, including Premium, and is reported as **402**, not 429. `baseURL` is a `var` so tests can point at an httptest server. Three API quirks are handled in `toEntry`: a running entry has `stop: null` and a **negative `duration`** (the "-1 convention"), so its duration is timed from the start and flagged `Running`; `description`/`project_name`/`tags` are all nullable, hence the `*string` fields in `entryJSON`; and bounds are sent as **RFC3339 with an offset** and re-checked client-side, because Toggl stores UTC but renders in the account's *profile* timezone. `Lookback` (~3 months) is checked before any request so an out-of-range window costs no quota, returning the `ErrBeyondLookback` sentinel. `Label(d)` formats a duration as "2h 15m" for the report. Only the work of one client is reported: the `clientName` constant (`DPGA`) is matched case-insensitively against each entry's `client_name` in `toEntry`, and an entry booked to any other client — or to none — is dropped there, so it never reaches a digest, a total or a report. It is a constant rather than an env var for the same reason the lookback window is not configurable. `ticketRe` (`#\d+\b`) finds the owner's GitHub-style ticket flags anywhere in an entry's description *or* tags; `tickets()` collects them distinctly and in order onto `Entry.Tickets`, `Entry.Flagged()` reports whether any were found, and `Digest.Unflagged` sums the duration of the entries with none. Unflagged entries are the reason the package exists: work with no ticket has no commit or pull request either, so nothing else in the digest records it. There is deliberately **no** total across every entry — that number is precisely the one that must never be reported, so the type does not carry it.
- `internal/gcal` — wrapper around the Google Calendar v3 API (`google.golang.org/api/calendar/v3`). `New(ctx, credsJSON, calendarID)` builds a read-only client from a Google credentials JSON via `option.WithCredentialsJSON` — either **authorized-user** creds (from `gcloud auth application-default login --scopes=…calendar.readonly`, reading the signed-in user's own calendar with full event details — the approach used here, since Workspace domains often restrict external calendar sharing to free/busy) or a **service-account** key (needs the calendar shared read-only with the SA email). `Events(ctx, since, until)` lists the calendar's timed events in the window (`SingleEvents(true)` expands recurrences; paginates on `NextPageToken`), returning a `Digest`. `toEvent` drops standup noise: cancelled instances, all-day events (a `Start.Date` with empty `Start.DateTime`), and events the owner declined (the `Self` attendee's `ResponseStatus == "declined"`).
- `internal/gdrive` — wrapper around the Google Drive v3 API (`google.golang.org/api/drive/v3`, already in the module `internal/gcal` depends on — the backup added no new dependency). `New(ctx, credsJSON, folderName)` builds a client from the *same* credentials JSON as `gcal`, scoped to **`drive.file`** — a non-sensitive scope needing no Workspace admin grant and no app verification, which grants access only to files this app created. That scope is why the folder is configured by **name, not ID**: a folder made by hand in the Drive UI is invisible under `drive.file`, so `ensureFolder` looks for the bot's own folder of that name and creates it in My Drive on first use (the ID is then cached on the `Client` for the rest of the run). `Upload(ctx, name, content)` looks the name up in that folder and *updates in place* when it exists, so re-running a report keeps one file and one stable link per period, mirroring how `monthly.Write` overwrites its local copy; it returns the file's `webViewLink`. `escape` quotes names for Drive's query syntax (single-quote delimited, backslash-escaped).
- `internal/monthly` — the CLI-only monthly report's plumbing (no network calls of its own). `Ask(in, out, now)` prompts for a year and month, both defaulting to the month before `now`, validating ranges and reading both answers from one buffered reader. `Window(year, month)` returns the half-open `[since, until)` covering that month in the local timezone. `Label(year, month)` names it ("June 2026") for the heading and prompt. `Write(dir, year, month, report)` creates `dir` (the exported `Dir` = `reports`, gitignored), writes `<year>-<month>-monthly-report.md` trimmed to start on its heading and end in exactly one newline (the model sometimes pads its reply), overwriting a previous run, and returns the path.
- `internal/claude` — thin wrapper around the Anthropic Messages API. `New()` builds a client; `Ask(ctx, system, prompt)` sends a single prompt and returns the reply. `StandupSystem(period)` builds the system instruction used to turn a digest (pull requests, commits, calendar meetings, and tracked time) into a standup update; `period` is the reporting-window label that opens the message ("My <period> was about:") — `main` passes `cfg.PeriodLabel()` ("yesterday" on weekdays, "Friday" on Monday, matching `Since`). `MonthlySystem(period)` is the monthly counterpart: same digest shape, but it asks for a themed markdown report opening on a `# <period>` heading rather than a chat message (its section list covers what shipped and what progressed — the old "anything left open" section was dropped, since it invited exactly the forward-looking notes `pastTenseRule` forbids), and it puts the tracked-time work in a section of its own (`## Work without a paper trail`, last, omitted when empty) where the standup just folds it into the bullets. Both share `pastTenseRule`, which keeps the reports to what was actually done — commit bodies, pull request descriptions and time entries are full of notes about what still has to happen ("the index will need a redeploy", "watch the cron"), and a summarizer repeats them as though a reminder were a result, so the rule names follow-ups, next steps, TODOs, reminders, pending deployments/migrations, caveats and known issues explicitly rather than trusting "past tense" to cover them; unfinished work is still reported, by its progress rather than by what remains. They also share the `deliveredRule` constant, which explains render's `DELIVERED` marker, `ticketRule`, which explains the `NO TICKET` marker and insists that work be reported from the entry's own description since the section is its only record, and `timeRule`, which explains the tracked-time section: every line in it is work that produced no commit or pull request, so it must be reported from the entry's own description and never linked or called a commit. It is worded for the section's *absence* as well, since the prompt is a constant while the section is conditional, and it ends by forbidding hours for any other work as well as inventing hours when the section is missing. and both require every bullet to cite the pull requests behind it as markdown links on their titles (pull requests only — commits are not linked).
- `internal/slack` — posts messages to a Slack incoming webhook using stdlib `net/http` (no new deps). `New(webhookURL)` mirrors `gh.New(token)` (the URL is the credential); `Post(ctx, text)` sends `{"text": text}` as JSON with a 10s-timeout client and treats any non-`200`/non-`ok` response as an error. `toMrkdwn` converts the two bits of standard Markdown Claude emits that Slack's mrkdwn spells differently — `**bold**` becomes `*bold*`, and `[text](url)` becomes `<url|text>` (`` `code` `` is the same in both). The link conversion matters because the standup prompt now asks for pull request links; `linkRe` requires a space-free URL with no closing paren so ordinary prose like `[see below] (it landed)` is left alone. `main` posts only when `SLACK_WEBHOOK_URL` is configured.

## Commands

```bash
go run .          # run the standup
go run . monthly  # write a monthly report (prompts for year/month)
go build ./...    # compile
go test ./...     # run all tests (every internal package has tests)
go test -run TestName ./path  # run a single test
go mod tidy       # sync go.mod/go.sum after changing imports
```

A `Makefile` wraps these for humans (`make` alone lists the targets: `standup`, `monthly`, `build`, `test`, `check`, `vet`, `fmt`, `tidy`, `clean`). It is a convenience wrapper only — no build logic lives there, and CI calls the `go` commands directly. `make check` runs fmt + vet + test, i.e. everything `.github/workflows/test.yml` checks; note `make fmt` only _reports_ unformatted files rather than rewriting them.

Requires Go 1.26+.

## Configuration

Env vars are loaded from a `.env` file via `godotenv.Load()` in `config.Load()` (`.env` is gitignored). Every variable below is required except `SLACK_WEBHOOK_URL` and the calendar pair — `config.Load()` errors naming any required one that is unset (or malformed). Copy `.env.example` to `.env` and fill in:

- `GH_PAT` — GitHub personal access token.
- `ANTHROPIC_API_KEY` — read automatically by the Anthropic SDK. `claude.New()` / `anthropic.NewClient()` take no explicit key argument. Always needed, since the digest is always summarized with Claude.
- `AUTHOR_EMAILS` — comma-separated git emails to attribute commits to in `OrgCommits`. `config.Load()` errors if it yields no email.
- `GH_ORG` — the organization the digest is built from. The reporting window is no longer configurable; `config.Since()` derives it from the weekday.
- `TOGGL_API_TOKEN` — optional; switches into the digest the time tracked for the **DPGA** client against **no** `#123` ticket — the work no commit records (see `internal/toggl`). Time logged for any other client is dropped before anything else, and time logged against a ticket is dropped too — its duration is never reported. A Toggl Track API token from the profile page. Free-plan API access is fine. Two limits are handled rather than hidden: the ~3-month history window (an older `monthly` run warns on stderr and omits the section) and the 30-requests-per-hour user-scoped quota (each run makes exactly one request).
- `SLACK_WEBHOOK_URL` — optional Slack incoming-webhook URL. When set, the summary is posted there in addition to being printed; when empty, it is only printed.
- `GOOGLE_CREDENTIALS_JSON` — optional; the credential shared by both Google features. A Google credentials JSON (single line): authorized-user creds from `gcloud auth application-default login`, or a service-account key. List every scope you need in **one** login, since the command replaces the whole ADC file: `--scopes=openid,https://www.googleapis.com/auth/calendar.readonly,https://www.googleapis.com/auth/drive.file`. Setting it without switching on at least one feature below is an error.
- `GOOGLE_CALENDAR_ID` — optional; switches calendar events into the digest. The calendar to read (your email, or `primary`). With a service account, the calendar must be shared with the SA email. Needs `GOOGLE_CREDENTIALS_JSON`.
- `GOOGLE_DRIVE_FOLDER` — optional; switches on the Drive backup of finished reports (both the daily standup and the monthly report). The **name** of the My Drive folder to upload to, e.g. `standup-bot` — a name rather than an ID because `drive.file` only sees files the bot created, so the bot creates the folder itself on first run (see `internal/gdrive`). Needs `GOOGLE_CREDENTIALS_JSON` carrying the `drive.file` scope. A service-account credential technically works but puts the files in the service account's own Drive, where no human can browse them.

## Scheduling

`.github/workflows/standup.yml` runs `go run .` on a cron (`0 5 * * 1-5` — 05:00 UTC, Mon–Fri) and via `workflow_dispatch`. That's 07:00 Budapest during summer (CEST); GitHub cron is UTC with no DST support, so in winter (CET) it lands at 06:00 Budapest. Cron may be delayed a few minutes under GitHub load. Secrets `GH_PAT` / `ANTHROPIC_API_KEY` / `SLACK_WEBHOOK_URL` / `TOGGL_API_TOKEN` / `GOOGLE_CREDENTIALS_JSON` and repo Variables `GH_ORG` / `AUTHOR_EMAILS` / `GOOGLE_CALENDAR_ID` / `GOOGLE_DRIVE_FOLDER` feed the job's env (the `GOOGLE_*` group is optional; each feature variable needs the credential alongside it). The scheduled standup backs itself up to Drive whenever `GOOGLE_DRIVE_FOLDER` is set — note the secret must then hold a credential whose grant includes `drive.file`, so re-run the ADC login and refresh the secret when adding it. The reporting window is derived from the weekday in `config.Since()` (Monday reaches back to Friday, other weekdays to yesterday), so Fri + the weekend are covered with no lookback variable to tune.

The monthly report has no automation by design: it is interactive (it prompts on stdin) and run by hand with `go run . monthly`. Its Drive backup rides along with that manual run. Nothing in `.github/workflows` invokes it, and the standup workflow's bare `go run .` is unaffected by the subcommand dispatch.

`.github/workflows/test.yml` is CI: on push to `main`, on any pull request, and via `workflow_dispatch` it runs `go build ./...`, `go vet ./...`, and `go test -race -cover ./...`. It needs no secrets or variables.

## Notes

- The Claude model is referenced via SDK constants (e.g. `anthropic.ModelClaudeOpus4_8`), not raw strings.
- `internal/gh` authenticates by injecting a `Bearer` token through a custom `http.RoundTripper` that clones the request before mutating headers — follow that pattern rather than mutating requests in place.
- GraphQL selections are expressed as Go structs with `graphql:"..."` tags, including inline fragments (`... on Issue`); `Item` flattens the union content into one shape.
